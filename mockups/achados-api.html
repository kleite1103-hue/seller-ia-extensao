01 DOIS CAMPOS DA SHOPEE ESTÃO MENTINDO

Descobri cruzando os números da campanha do Vaso Decorativo Preto. Isto não é opinião: é aritmética.

O CAMPO "CPC" NÃO É CUSTO POR CLIQUE
// campanha 110778786 — Vaso Decorativo Moderno Preto
cost = 11.074.853 micro = R$ 110,75
click = 2.740
broad_order = 21

CPC verdadeiro = 110,75 ÷ 2.740 = R$ 0,04
campo cpc da API = 527.373 micro = R$ 5,27

// mas repare:
11.074.853 ÷ 21 pedidos = 527.374 ← é isso

O campo chamado cpc é, na verdade, o custo por PEDIDO. E o campo cpdc devolve exatamente o mesmo número. Quem lê cpc como custo por clique erra por 130 vezes nesta campanha.

O CAMPO "CPM" TAMBÉM NÃO É CPM
impression = 66.150 · cost = R$ 110,75

CPM verdadeiro = 110,75 ÷ 66.150 × 1000 = R$ 1,67
campo cpm da API = 11.199.653 micro = R$ 112,00

O valor devolvido é praticamente o custo total, não o custo por mil. Já tínhamos anotado isso no código — agora está provado com número.

Por que isso vale dinheiro: qualquer ferramenta concorrente que leia cpc e cpm direto da API está mostrando número errado para o vendedor. Nós derivamos os dois. É diferencial verificável.

E mais uma calibragem confirmada: ctr, cr e atc_rate vêm como fração, não porcentagem. ctr = 0.0414 é 4,14%. Conferido: 2.740 ÷ 66.150 = 0,0414.

04 A FAIXA DE ROAS QUE VALIDA O CARD APROVADO

A rota get_recommended_target_roi devolve exatamente a barra que desenhamos no card final.

lower_bound = 240.000 → 2,4x · percentil 80
exact       = 510.000 → 5,1x · percentil 50
upper_bound = 1.000.000 → 10,0x · percentil 20
hard_upper_bound = 50,0x

São os mesmos 2,4x / 5,1x / 10x do card aprovado. Aquela barra não era ilustração — era esta rota. Ela está capturada e só o valor do meio (5,1x) está sendo mostrado hoje.

Atenção a uma armadilha de nomenclatura: lower_bound tem o percentil 80 e o valor menor. Os nomes estão invertidos em relação à intuição. Ler errado inverte o conselho.

07 O DIAGNÓSTICO DE PRODUTO DA PRÓPRIA SHOPEE

Duas rotas que nunca olhamos: mydata/product/diagnosis/items e /sku.

// 17 produtos diagnosticados pela Shopee
itemid · title · image · status
d1 = 15 · d2 = 2 · d3 = "13.33"

// e por variação (SKU):
modelid · model_name = "Bege,GG-46"
d1 = 3 · d2 = 1 · d3 = 33.3333

Os campos d1, d2 e d3 ainda precisam ser decodificados — a proporção d2 ÷ d1 × 100 = d3 bate nos dois exemplos (2÷15=13,33% e 1÷3=33,33%). É uma taxa de alguma coisa por produto e por variação, calculada pela Shopee. Descobrir o que são d1 e d2 é um experimento pequeno e provavelmente valioso.
